# France Storecove format artifacts

These files are reviewed candidate HTTP request bodies for Storecove France F10
e-reporting. Each `.request.json` file is the exact compact JSON body captured at
the final HTTP client boundary. Reports are independent per `legalEntityId` and
contain exactly one transaction or payment section.

Normal tests are read-only and fail when generated bytes differ from the
committed candidates. Regeneration is deliberately explicit:

```bash
UPDATE_STORECOVE_ARTIFACTS=1 php vendor/bin/phpunit tests/Unit/FranceEReporting/FranceEReportArtifactAssessmentTest.php
```

The candidates are not Storecove-qualified final reports yet. There is no
Storecove sandbox available for this integration. The manifest therefore keeps
every variant `UNPROVED` until Storecove supplies the exact F10 XML produced for
these payloads or an authorized real-data production canary produces it. That
XML must then pass the pinned AIFE rules and scenario-value comparison. Never
send synthetic or test data through the live PDP/PPF path.

Production activation still requires that evidence. If vendor-produced XML is
unavailable and a real-data canary is required, operations must first ensure
that France reporting is enabled only for the specifically authorized canary
company.
